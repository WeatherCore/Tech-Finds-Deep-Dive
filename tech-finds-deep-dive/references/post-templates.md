# 8 种小红书技术内容爆文结构模板

> skill 步骤 5 从这 8 种里选 1 种最贴合的。
> 每个模板包含:适用场景/人设、结构骨架、标题公式、话题标签、字数建议。
> 完整范文(标题+正文+标签的实际产出形态)见 `references/example-posts.md`。

---

## 模板 1:"XX 天从小白到 XX"成长记

**适用场景**:学习路径类、入门到实战类项目
**适合人设**:学生党、转码人
**结构骨架**:
- 开头 hook:具体天数 + 起点状态("X 天前我还是个 YY")
- 中间:阶段递进(Day1 学了啥 → Day7 做了啥 → Day30 项目成了)
- 关键转折:遇到一个具体卡点 + 怎么解决(体现项目帮助)
- 结尾:现在的状态 + 给同路人的建议
- CTA:关注追更 / 评论区交流

**标题公式**:`{天数}从{起点}到{终点},这个项目是关键`
**话题标签**:#转码 #自学编程 #程序员 #学习打卡 #程序员日常
**字数**:500-800

---

## 模板 2:"我用 XX 做了 YY,结果..."成果展示

**适用场景**:工具类、应用类、有可见成果的项目
**适合人设**:学生党、转码人、技术博主
**结构骨架**:
- 开头 hook:成果先行("我用 XX 做了个 YY,效果是 Z")
- 中间:展示项目能做什么(配图/截图描述)+ 怎么做的(简略)
- 对比:跟之前用别的方法做的对比
- 结尾:开源/教程地址 + 鼓励大家试

**标题公式**:`我用{项目}做了{成果},结果{意外效果}`
**话题标签**:#程序员 #开源项目 #技术分享 #独立开发 #程序员日常
**字数**:400-700

---

## 模板 3:"XX vs YY 对比测评"

**适用场景**:框架/库/工具对比类
**适合人设**:技术博主、转码人
**结构骨架**:
- 开头 hook:为什么对比("最近在选 XX,纠结 YY 和 ZZ")
- 中间:多维度对比表(性能/学习曲线/生态/文档/社区)
- 实测数据:具体跑分/代码量/启动时间等
- 结尾:不同场景下的推荐(不绝对,讲 trade-off)

**标题公式**:`{A} vs {B} 实测,选{场景}的看这篇`
**话题标签**:#技术选型 #程序员 #开源项目 #技术分享 #前后端
**字数**:600-1000

---

## 模板 4:"XX 避坑指南"

**适用场景**:有常见误区的项目、易踩坑的技术栈
**适合人设**:转码人、技术博主、求职者
**结构骨架**:
- 开头 hook:踩过的坑("我用 XX 踩了 N 个坑,记下来给后来人")
- 中间:N 个具体坑 + 每个坑的解决方案(代码片段/截图)
- 高级坑:别人没提过的 1-2 个隐藏坑
- 结尾:正确用法总结

**标题公式**:`{项目}踩了{N}个坑,这份避坑指南码住`
**话题标签**:#程序员 #避坑指南 #技术分享 #开发日常 #程序员日常
**字数**:600-900

---

## 模板 5:"开源分享:XX 项目"

**适用场景**:开源项目推广、自研工具分享
**适合人设**:技术博主
**结构骨架**:
- 开头 hook:项目是什么 + 解决什么问题
- 中间:技术亮点(架构/性能/工程化)+ 跟同类项目的差异
- 源码/文档地址 + star 数(若有)
- 贡献机会/后续 roadmap

**标题公式**:`开源分享:{项目} - {一句话定位}`
**话题标签**:#开源项目 #程序员 #GitHub #技术分享 #独立开发
**字数**:500-800

---

## 模板 6:"简历项目:我用 XX 拿到 offer"

**适用场景**:简历级项目、求职作品集
**适合人设**:求职者、学生党
**结构骨架**:
- 开头 hook:offer 信息(拿到 X 家 offer)+ 项目在简历的位置
- 中间:项目核心(做了啥 + 怎么做)+ 面试官追问的 3 个点 + 怎么答
- 反差:跟其他 toy demo 项目的差异
- 结尾:简历项目选择建议

**标题公式**:`简历项目写{项目},面试{N}家拿到{N}offer`
**话题标签**:#简历项目 #面试 #程序员面试 #秋招 #求职
**字数**:600-900

---

## 模板 7:"学生党必备 XX 工具"

**适用场景**:学生向工具、入门级项目、教学类
**适合人设**:学生党
**结构骨架**:
- 开头 hook:学生党场景("课设要交了/秋招了/简历没东西写")
- 中间:工具/项目解决的具体学生痛点(3 个)
- 上手指南:学生党怎么用(配 demo)
- 结尾:同类工具对比(可选)

**标题公式**:`学生党必备:{项目},解决{学生痛点}`
**话题标签**:#学生党 #程序员 #大学生 #计算机专业 #秋招
**字数**:400-600

---

## 模板 8:"XX 源码精读 / 技术拆解"

**适用场景**:有架构亮点、值得拆源码的项目
**适合人设**:技术博主
**结构骨架**:
- 开头 hook:为什么拆这个项目(亮点先行)
- 中间:核心模块拆解(3-5 个关键文件/类/函数)
  - 每个模块:做什么 + 怎么实现的 + 设计妙在哪
- 反直觉点:1 个"看起来奇怪但实际巧妙"的设计
- 结尾:学到的工程化思路

**标题公式**:`{项目}源码精读:{N}个核心模块拆解`
**话题标签**:#源码精读 #程序员 #技术拆解 #开源项目 #技术分享
**字数**:800-1200

## 选择逻辑(skill 步骤 5 用)

| 产品品类 | 优先模板 |
|---|---|
| 教学类/入门项目 | 模板 1 成长记 / 模板 7 学生党必备 |
| 工具类/应用类 | 模板 2 成果展示 |
| 框架/库 | 模板 3 对比测评 / 模板 8 源码精读 |
| 开源项目 | 模板 5 开源分享 |
| 简历级项目 | 模板 6 简历项目 |
| 有踩坑价值的项目 | 模板 4 避坑指南 |
| 有架构亮点的项目 | 模板 8 源码精读 |

**人设 × 模板匹配建议**:
- 学生党 → 模板 1/2/6/7
- 转码人 → 模板 1/2/3/4
- 技术博主 → 模板 3/4/5/8
- 求职者 → 模板 4/6

skill 在步骤 5 同时考虑"产品品类"和"自动匹配的人设"两个维度选模板。
