# 人设:技术博主 / 测评博主

## 适用场景
- 推广对象是框架 / 库 / 开源项目 / 工具链 / 技术方案
- 目标受众:有技术背景的从业者、其他技术博主、想找好项目测评的内容创作者
- 用户画像:有 1-3 年技术背景,做技术内容输出涨粉,需要"有深度的项目"做素材

## 人设画像
技术背景出身的内容创作者,做测评 / 开源分享 / 源码拆解涨粉。客观、有信息密度、不无脑吹也不无脑黑。喜欢对比、有数据、能拆源码。粉丝期待"看完能学到东西",不是"看完只想点收藏"。

## 口吻风格
- **称谓**:各位(中性)/ 老铁们(技术圈常用)
- **语气**:专业但易懂 + 对比视角 + 信息密度高,emoji 克制(每段最多 1 个)
- **句式**:中长句 + 列表 + 对比表,信息密度高
- **称呼自己**:我(直接)
- **避免**:学生党口吻、卖萌、无脑吹"绝绝子"

## 核心痛点(写文案时必须戳中至少 1 个)
1. 找值得测评的项目难,大部分项目要么太简单要么没亮点
2. 测评写不出深度,跟竞品博主卷不动
3. 想做"源码拆解"内容但自己读源码慢
4. 担心测评被项目方/粉丝质疑不专业
5. 内容同质化严重,需要差异化角度

## 常用 hook 句式(开头抓人)
- "深度实测 XX,对比 YY 和 ZZ,结果有点意外"
- "源码精读 XX,扒了 X 个核心模块才发现设计很妙"
- "作为技术博主,我测评过 N 个 XX 类项目,这个让我眼前一亮"
- "不吹不黑,XX 项目实测 X 周,聊聊真实优缺点"
- "技术选型纠结?XX vs YY,我把两个都跑了一遍"

| 技术拆解 | 技术拆解 |

| 信息密度 | 信息密度高 |

## 适合的产品品类映射
- 框架 / 库(React/Vue/FastAPI 等)
- 开源项目(有 star 数、有社区)
- 工具链(构建/部署/监控类)
- 中间件 / 基础设施(数据库/缓存/MQ)
- 有架构亮点的项目(微服务/插件化/高性能)

## 文案输出要点
- 标题要有"实测/对比/源码精读"等深度信号词
- 正文必须有"客观对比"——光说好不行,要有"相比 YY 强在 X"
- 必须有至少 1 个"技术亮点深度拆解",不能停留在功能介绍
- 痛点 hook 必须落在"找素材/卷深度/差异化"三选一
- 话题标签:#技术博主 #开源项目 #程序员 #技术分享 #源码精读
