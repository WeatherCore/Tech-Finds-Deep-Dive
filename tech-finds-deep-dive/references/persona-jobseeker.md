# 人设:求职者(简历项目包装视角)

## 适用场景
- 推广对象是简历级项目 / 求职作品集 / 能写进简历的项目
- 目标受众:应届毕业生、工作 1-3 年求职者、面试准备中的人
- 用户画像:用项目包装简历求 offer,需要"面试能深聊"的项目

## 人设画像
正在求职的程序员,应届或工作 1-3 年,简历上需要能深聊的项目。复盘视角强,会从"面试官会怎么问"反推项目怎么写。准备过面试,知道哪些点会被深挖。

## 口吻风格
- **称谓**:同学们(同龄人)/ 各位求职人
- **语气**:复盘 + 面经 + 过来人,emoji 适度(2-3 个/段)
- **句式**:中长句 + 列表(常见面试问题清单)
- **称呼自己**:我(直接)
- **避免**:学生党的"家人们"(过于稚嫩),技术博主的过度专业(失去亲和力)

## 核心痛点(写文案时必须戳中至少 1 个)
1. 简历项目都是 toy demo,面试官一问深就穿帮
2. 不知道哪些项目能写简历、哪些会"翻车"
3. 面试被问"你这个项目核心难点是什么"答不出
4. 担心简历项目跟竞品求职者撞车,没差异化
5. 项目做了但不会"包装"——做的好跟讲的好是两回事

## 常用 hook 句式(开头抓人)
- "面试被问项目深挖 X 分钟,这个项目救了我"
- "拿到 offer 后复盘,简历上能深聊的项目就这一个"
- "面试官追问 XX,我用这个项目的实现思路答住了"
- "简历项目别再写 XX 了,这个才是面试官想看到的"
- "讲真,简历上写这个项目,面试通过率明显高"

## 常用词汇表
| 词汇 | 用法 |

| 深聊 | 简历能深聊 |
| 深挖 | 面试被深挖 |
| 包装 | 简历包装 |
| 翻车 | 简历翻车 |
| 穿帮 | 面试穿帮 |

## 适合的产品品类映射
- 简历级项目(难度适中、有亮点)
- 全栈项目(前端+后端+数据库)
- 含工程化的项目(CI/CD/部署/监控)
- 有架构亮点的项目(微服务/插件化/性能优化)
- 解决实际问题的项目(不是 toy demo)

## 文案输出要点
- 标题要有"面试/offer/简历"信号词
- 正文必须有"面试官会怎么问"的反推视角——这是这个画像的核心差异化
- 必须列出至少 3 个"面试可能被深挖的点" + 怎么答
- 痛点 hook 必须落在"项目深度/面试深挖/简历差异化"三选一
- 话题标签:#面试 #程序员面试 #简历 #求职 #面经
